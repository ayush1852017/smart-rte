# Phase 1–8b Independent Audit

**Scope:** read-only verification of the Phase 1–8b canonical-architecture migration against source, tests, and gate scripts — not against the phase completion reports. Conducted 2026-08-06 on branch `core-implementation` at commit `38ee499`, clean working tree.

**Method:** every claim below was checked against source (file:line), by running the actual test suites (`pnpm --filter smartrte-core test`, `pnpm --filter smartrte-react test`), and by running every gate script (`node scripts/check-*.mjs`, and `pnpm run lint` end-to-end). Two of the most consequential findings (`pnpm lint` fails; `canonicalAuthorityFlag` defaults to off) were independently re-verified by direct command execution and file read after the initial research pass, not taken on a single source's word.

---

## 1. Executive summary

The codebase is **not** in the state the phase reports describe, on the one dimension that matters most for a Phase 9 go/no-go: **the build's own gate is red**. `pnpm run lint` fails today, on a clean `core-implementation` tree, at `lint:phase3-contract`, and would fail again at `phase4`, `phase6`, `phase7`, and `phase8a` if the `&&` chain were not aborting early — all five failures stem from the same broken mechanism (a `MIGRATION_ADAPTER:` comment-marker census that no longer matches the adapter files it's counting). Nobody would see this by reading the phase docs; all of them report green gates as of their own commit. Underneath that, the frozen Phase 1/2/2.5 contracts (schema, node IDs, `SmartPos`, the twelve operations, transactions, normalization locality, history) hold up well under direct inspection and are the most trustworthy part of the codebase. The single biggest thing the team does not currently know: **the "canonical" toolbar and the "canonical" command layer are not what most of `packages/core/src/commands/` actually is** — that directory (50 command bindings) is entirely the legacy `SmartCommand`/`LegacyCommandContext` engine, not the pure `(document, scope, params, ctx)` canonical layer, which lives instead in `packages/core/src/foundation/*/commands.ts` (43 commands) and is not routed to by default because `canonicalAuthorityFlag.globalEnabled` is `false` out of the box — meaning every unconfigured consumer of this package today gets the 6,069-line legacy `ClassicEditor.tsx`, not the canonical editor the last three phases were built to validate.

## 3. Gate script audit

**Headline: `pnpm run lint` fails right now** (re-verified directly). It aborts at `lint:phase3-contract` with "canonical list migration adapter is missing from the tracked metric." Because the script is an `&&` chain, `phase4`, `phase6`, `phase7`, `phase8a`, and even the real per-package `tsc`-based lints **never run** in that invocation. Running each phase script individually confirms four more failures behind the first: `phase4-contract` ("Expected three feature adapters... source contains 0"), `phase6-contract` ("Feature adapter count is 0; Phase 6 cap is 3"), `phase7-contract` (same pattern), `phase8a-contract` ("must disclose 3 feature + 1 clipboard bridge; source=0, inventory=NaN"). Root cause is uniform: these five scripts count `MIGRATION_ADAPTER:` comment markers in `packages/react/src/adapters/`, and **zero such markers exist anywhere in the repo** (`grep -rn MIGRATION_ADAPTER packages/` matches only documentation, not source) — either the markers were removed in a later cleanup without updating the gates, or they were never actually added despite the docs claiming an adapter census.

None of the 9 scripts execute code, run the editor, or parse an AST. All are `readFile` + regex/`.includes()`/`matchAll` over either a fixed file list or an `rg` full-repo scan.

## 4. Findings by severity

### Critical

- **`pnpm run lint` fails on a clean tree at HEAD.** `scripts/check-phase3-contract.mjs` (and, if reached, `phase4/6/7/8a`) fail because the `MIGRATION_ADAPTER:` marker census has nothing to count — zero markers exist in `packages/react/src/adapters/` despite five gate scripts requiring 3–4 of them. This is not a flaky test; it reproduces deterministically on a clean checkout. Location: `scripts/check-phase3-contract.mjs`, `scripts/check-phase4-contract.mjs`, `scripts/check-phase6-contract.mjs`, `scripts/check-phase7-contract.mjs`, `scripts/check-phase8a-contract.mjs`. Impact: every contract these five scripts were meant to enforce (list purity, mark-tool count, table-grid sharing, atom security invariants, clipboard sanitize-order) has had zero automated enforcement for however long the marker removal has been unnoticed, and the per-package `tsc` lint step never runs when invoked via `pnpm run lint` because the chain aborts first.
- **The four "dormant" rollback bridges are reachable in the shipped default, not dormant.** `packages/react/src/canonicalAuthorityFlag.ts:18` sets `globalEnabled = false` and nothing in product code calls `setGlobal(true)` (only a test file does). `ClassicEditorAuthority.tsx` therefore routes every unconfigured `<ClassicEditor/>` consumer to `LegacyClassicEditor` (`ClassicEditor.tsx`, 6,069 lines), which uses the bridges directly. Impact: any security or correctness property that assumes "the bridges are unreachable, therefore lower-priority" is working from a false premise for the package's actual default behavior.

### High (blocks Phase 9 or misrepresents current architecture)

- **`packages/core/src/commands/` (50 command bindings, the directory Phase 3–7 reports describe as "the command layer") is entirely the legacy `SmartCommand`/`LegacyCommandContext` engine, not the pure canonical command template.** Every file there constructs a full `LegacySmartTransaction` internally rather than returning `SmartOperation[]`. The genuinely pure `(document, scope, params, ctx) => SmartOperation[]` layer — the one the canonical toolbar actually calls — lives in `packages/core/src/foundation/{marks,block,list,table,atom}/commands.ts` (43 commands) and is a separate, parallel implementation. `packages/core/src/command.ts:11-15` (legacy interface) vs. e.g. `packages/core/src/foundation/marks/types.ts:10` (canonical signature). Impact: any future audit, onboarding doc, or Phase 9 design that assumes "the command layer" is singular will be reading the wrong 50 functions.
- **10 of 10 audited toolbar capabilities (font family/size, text/background color, blockquote, block move/indent, list presets, DOCX, PDF, media-manager upload) are present in `foundation/`/`adapters/` but not wired into `CanonicalAuthorityEditor.tsx`.** Media insertion in the canonical toolbar is a literal `window.prompt(...)` (`CanonicalAuthorityEditor.tsx:238,249,254,284`) despite a full `MediaManager.tsx` component existing and being used by the legacy editor. Impact: the canonical editor is not close to feature parity for any consumer who would need these, despite the underlying commands being ready.
- **Format/serialization code (HTML writer, DOCX, PDF) lives entirely in `packages/react/src/adapters/`, not in `packages/core`.** `domSmartDocument.ts:311-344` (`serializeBlock`) is a single monolithic function with a long `if (block.type === ...)` chain covering every node type — exactly the shape a codec-per-feature refactor needs to break apart. `foundation/{marks,list}/formats.ts` are already per-feature (a head start, but only for DOCX run-property construction), so the codebase is in a half-migrated state for Phase 9's stated goal. Impact: Phase 9 cannot be "core work" as currently scoped — DOCX/PDF/HTML I/O logic isn't in core to consolidate; it would need to move packages first, or Phase 9 needs to explicitly include `packages/react/src/adapters/*Format.ts`.
- **Normalization is not local for structural edits.** `repair(document, schema)` (`normalization.ts:107`) walks the entire document on every non-text-only transaction (split, merge, move, any table/list structural op), bounded only by the 3-pass cap. This contradicts an unqualified "normalization is local" claim; it's local only for the common case (plain typing).

### Medium

- **`PositionLookup` is duplicated three times in `packages/react/src`** (`canonicalEditorRuntime.ts:75-83` and a second near-identical closure at `231-239`; `CanonicalAuthorityEditor.tsx:76-84`) despite a clean, single canonical implementation in core (`scope/resolveScope.ts:846-895`). `CanonicalAuthorityEditor.tsx` uses both the correct lookup (`positions.positionOf`) and its own ad-hoc `findNode` in the same file.
- **Legacy `commands/table.ts` reimplements the occupancy grid** (`buildTableGrid`, lines 38-69) with materially different failure semantics (strict null-on-overlap) than the canonical `occupancyGridFor` (tolerant, repairable) — a real behavioral fork, not just duplicated text, though it's confined to the legacy model.
- **`resolvePrecedingContentTarget` has exactly one consumer** (`list/input.ts:317`) despite being described as generalized across lists and blocks; no block-side backspace/merge logic exists to consume it.
- **Phase 8b documentation is stale relative to HEAD.** `PHASE_8B_DELTA_REPORT.md:161` reports 420 core tests passing; HEAD has 423, from 5 undocumented commits (`a174092` through `38ee499`) with no corresponding phase write-up, including commits that appear to touch exactly the media-URL-prompt gap the delta report lists as open (`0bad685`, `608c910`).
- **`check-phase8b-contract.mjs` exists, passes, and enforces nothing** — it is not referenced in `package.json`'s `scripts` block at all.

### Low

- Root `package.json`'s `katex` dependency is not imported by any published package's source — `ClassicEditor.tsx:1859` expects `window.katex` supplied by the host page. This is a real but undeclared peer expectation, not a version/security issue (KaTeX and DOMPurify versions are current, caret-pinned, no obvious advisories from version numbers alone — not checked against a live CVE feed).
- Debt markers (`as any`: 54, `@ts-ignore`: 4, non-null assertions: ~22) are cleanly concentrated in the legacy `ClassicEditor.tsx` and test files; the `foundation/` contract layer has zero `as any`, zero `@ts-ignore`, and only 4 justified `.find(...)!` patterns. This is a genuinely clean result, not padding.
- No `TODO`/`FIXME`/`HACK` anywhere in source (0 occurrences).

## 7. Addendum — post-publication corrections

This section records corrections made after external review of §4–§6, resolving the open question above and recalibrating two findings. Original findings above are left as originally written; this section is the correction layer, not a rewrite.

**The `MIGRATION_ADAPTER` marker loss is a dated, mechanically explained regression, not evidence of prior false reporting.** `git log -p -S "MIGRATION_ADAPTER" -- packages/react/src/adapters` shows commit `033c975` ("refactor(react): remove active DOM authority primitives", Wed Aug 5 2026 12:34:50 +0530) renamed the marker to `ROLLBACK_ADAPTER:` in all three DOM bridge files in one deliberate edit, and in the same commit added `scripts/check-phase8b-contract.mjs`, which explicitly forbids the *old* marker string in product paths — the rename and the new gate are internally consistent with each other. What didn't happen: `check-phase3/4/6/7/8a-contract.mjs` were not updated or retired to match, so they kept requiring a marker that had just been intentionally removed. Three subsequent phase-8b documentation commits (`d815631`, `e8fb7a1`, `962f2cf`) landed after this without `pnpm lint` apparently being re-run in full — that's a real process gap (docs shipped on top of a broken build), but a materially smaller one than "the reports were never actually gated." Fix: retire or rewrite the five stale gates around what they should be checking behaviorally (see §3), not the marker they lost track of.

**Critical finding "four rollback bridges reachable by default" is downgraded.** `canonicalAuthorityFlag` defaulting to off, with legacy `ClassicEditor` as the shipped default, is exactly what an unpromoted Phase 8b (status: HOLD) is supposed to look like — not a defect. What's actually wrong is the word "dormant" in `docs/MIGRATION_ADAPTER_INVENTORY.md:5,18`, which describes bridges that are in fact the live default path until the flag is promoted. This is now a **Medium** documentation-accuracy finding, not Critical: correct the inventory doc to say "default path until flag promotion" so nobody deprioritizes work on the false premise that this code is unreachable.

**New Medium finding: the 32MB history byte budget creates a silent usability cliff for table-heavy documents, not a crash risk.** At ~1.6MB per table-operation history entry (`PHASE6_CARRY_FORWARD_AUDIT.md`), a 32MB budget (`history.ts:6`) holds roughly twenty undo steps before silent eviction for a user doing sustained table editing — no warning, no indication to the user that older undo history is gone. The crash risk this was meant to bound is real and handled; the UX tradeoff it introduces instead has not been a deliberate product decision.

**Normalization locality claim needs to stay qualified going forward.** §2/A6 already notes this, but it's worth restating plainly since it's been referenced unqualified before and table/list structural edits are routine, not rare: "normalization is local" is true for plain typing only. Any structural edit (split/merge/move, all table and list operations) triggers a whole-document `repair()` pass, capped at 3 iterations but not scoped to a subtree (`normalization.ts:107`).

**`packages/core/src/commands/` renamed to `packages/core/src/legacyCommands/`.** Matches the codebase's existing `Legacy`-prefixed type naming (`LegacyCommandContext`, `LegacySmartTransaction`). All 22 import references updated; verified via `tsc --noEmit` and full test suite (423 core / 235 react, unchanged counts). Commit `f1cc048`.

**Phase 9 scope decision: distributable.** This resolves §5 item 3, and it is a materially bigger decision than it looked when first raised, because it is not prospective: `npm view smartrte-core` and `npm view smartrte-react` both resolve today, at versions (`0.2.1`, `0.3.4`) matching the local `package.json` exactly, with `repository.url` pointing at this exact GitHub repo, last published 2026-07-14 and 2026-07-15 respectively. Neither package's `package.json` sets `"private": true`; both carry `publishConfig: { access: "public" }`. **This codebase is already a live, publicly-installable package, not a future one** — the internal/distributable question wasn't hypothetical, it was already answered by the publish history before this audit started.

Going with "distributable" resolved converts two earlier findings from packaging debt into live defects affecting real external consumers today:

- **§4 Low, `window.katex` global expectation, is escalated to High.** Any current npm consumer of `smartrte-react` who renders a formula node gets a runtime failure unless they separately know to load KaTeX as a global on `window` — this isn't documented as a peer dependency anywhere a consumer would see it before hitting the failure (`ClassicEditor.tsx:1859`, `const katex = (window as any).katex`). Fix: declare `katex` as a real `peerDependency` in `packages/react/package.json` (it currently isn't a dependency of that package at all — only the monorepo root has it, for the playground), or bundle it.
- **§4 High, DOCX/PDF/HTML format code living in `packages/react/src/adapters/` rather than `packages/core`, is confirmed as a real gap, not a hypothetical one.** A consumer building a non-React integration against the already-published `smartrte-core` (whose own npm description says "framework-agnostic document model and editing primitives") has no path to DOCX/PDF import/export today — that logic only exists inside the React package. Phase 9's codec-per-feature consolidation should target `packages/core`, which means `packages/react/src/adapters/{docxFormat,styledDocxFormat,portableDocxAtoms,pdfFormat,pdfImport}.ts` need to move (or be reimplemented framework-agnostically) into core as part of — not after — Phase 9, rather than being scoped out of it.
