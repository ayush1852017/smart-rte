# Phase 9–12a Independent Audit

**Scope:** read-only verification of Phases 9 through 12a (format codecs/package boundary, plugin ownership, production hardening, editor interaction surface, versioning/comments/suggestions) against source, tests, and gate scripts — not against phase completion reports. Conducted 2026-08-25 on branch `core-implementation`, HEAD `477a135` (committed 2026-08-18), **working tree not clean**: 151 modified/untracked paths, comprising the entire uncommitted Phase 12a (versioning/comments/suggestions) body of work plus several other in-flight files (see §0). All verification below was run against this exact working tree, since that is what "current state of the project" actually means today — but the fact that a full v1.1 feature phase sits uncommitted on top of a phase-8b-era HEAD is itself a finding, not a neutral fact, and is called out explicitly.

**Method:** every claim below was checked against source (file:line), by running the actual test suites (`pnpm --filter smartrte-core test`, `pnpm --filter smartrte-react test`), the actual full lint chain (`pnpm run lint`, all 12 gate scripts plus per-package `tsc`), the actual full e2e suite exactly as `packages/react/package.json`'s `e2e` script defines it (`pnpm --filter smartrte-react run e2e` — all 10 spec files × 3 browser projects, unfiltered, per the standing lesson in `docs/bugs/full-e2e-suite-definition-was-incomplete.md`), and `pnpm audit` at the repo root. Two new bugs were found and filed during this pass (§7); no existing `docs/bugs/` entry was found to be stale enough to require a status change, though one ("Open," §2) was independently re-confirmed still accurate rather than assumed.

---

## 0. The dirty working tree

`git status` at the start of this audit showed 151 changed paths on top of a committed HEAD (`477a135`) that is itself dated 2026-08-18 — i.e., the entire Phase 12a feature set (`packages/core/src/foundation/{comments,suggestions,versioning,annotations}/`, `packages/react/src/components/{CommentMarkers,CommentThreadPanel,SuggestionPanel,StructuralSuggestionMarkers,VersionHistoryPanel,ContextMenu,MediaOverlay,TableResizeHandles,ColorPickerPopover}.tsx`, three new e2e spec files, the mammoth `findLevel` fix, and roughly 40 other modified files) exists only in the working tree, not in any commit. `docs/PHASE_ROADMAP_8B_12B.md`'s own Phase 12a closeout note (dated 2026-08-25, the same date as this audit) is itself one of the uncommitted files. This means: everything this audit verifies as "passing" is verifying uncommitted work — a `git stash` or a bad `git clean` would currently lose the entirety of Phase 10, 11, 11.5, and 12a. This is an operational risk independent of whether the code itself is correct, and is the first thing that should happen before anything else: commit (or series-of-commits) this tree before doing anything destructive near it.

## 1. Executive summary

Phases 9 through 12a are in materially better shape than Phases 1–8b were at the time of the last independent audit, on exactly the dimensions that audit flagged as broken: **the full `pnpm run lint` gate chain passes today** (all 12 gate scripts, including the new Phase 8c and Phase 10 contracts, plus both packages' `tsc` lint), the collab-readiness gate (`check-phase8c-contract.mjs`) is real and behavioral rather than a marker census, the four "dormant" legacy rollback bridges and `canonicalAuthorityFlag` that the prior audit found were actually load-bearing in the shipped default are now **genuinely gone** (`git log` confirms `canonicalAuthorityFlag` was deleted outright, not just defaulted differently, in commit `cb05f88`), and both vitest suites match their claimed counts exactly on a fresh run: **core 693/693, react 130/130**. Running the actual full 3-browser e2e suite (444 tests, not the narrower definition a prior session mistakenly used) produced 435 passed / 7 skipped (all explained by in-code `test.skip` conditions) / **2 failed** — both on the same suggestions test, both a Playwright "test not found in worker" infra error rather than an assertion failure, and both non-reproducing when the same test was re-run in isolation across all three browsers. This is a real, if minor, discrepancy against the Phase 12a closeout's "stable across 3 runs × 3 browsers" claim, filed as a new bug (§7).

The two Phase 12a "deferred, not silently dropped" gaps hold up exactly as described: structural insertion suggestions are genuinely unsupported (`suggestions/structural.ts` only has a `"removeNode"` kind, no insertion equivalent), and the `mergedInto`/`retiredInto` orphan-policy wiring genuinely covers only 3 of roughly 40 `removeNode`/`replaceNode` construction sites in `packages/core/src/foundation` (table cell merge, list item merge, `deleteAcrossBlock`) — this audit independently re-derived that count via its own grep rather than trusting the roadmap's "~40" figure, and it holds.

A new, real "written, never rendered" bug (the third confirmed instance of this project's recurring pattern, after table `columnWidths` and `table_cell.textColor`) was found by a systematic schema-vs-renderer sweep: `image`/`video`/`audio`/`formula` nodes' `attrs.error` — the specific upload-failure reason — is written by `atom/lifecycle.ts` but never read by the canonical renderer; users only ever see a generic hardcoded failure message. Filed as `docs/bugs/atom-upload-error-reason-not-rendered.md`.

The mammoth/dependency-security story is the one area of this codebase that most convincingly demonstrates its own audit trail working as designed: the Phase 9 mammoth investigation's own revisit trigger ("before Phase 11's security review") fired, was actually checked (not silently skipped), found the `underscore` transitive CVE, fixed it via `pnpm.overrides`, and this audit's own fresh `pnpm audit` run independently confirms zero advisories remain against `mammoth`/`underscore`/`xmldom` and exactly the same 42 remaining dev-tooling-only advisories the Phase 11 security review already triaged and explained — including one critical (`vitest`, unexploitable in this repo's actual `vitest run` invocation) that this audit re-confirms rather than re-litigates.

**Overall assessment: materially healthier than the Phase 1–8b state, no Critical findings, three real Medium/Low findings (a new rendering gap, an uncommitted 151-file working tree, one non-reproducing e2e flake), and the codebase's own gates are, for the first time in this project's audit history, not the thing an independent pass needs to correct.** Phase 12b readiness is a separate, larger question addressed in §6.

## 3. Gate script audit

`scripts/check-phase8c-contract.mjs` (the collab-readiness gate) and `scripts/check-phase10-contract.mjs` (the plugin-ownership gate) are both new since the last audit and both materially better-built than the five gates that audit found broken:

- **Mechanism has changed for the better.** The Phase 1–8b gates counted `MIGRATION_ADAPTER:` comment markers — pure text census, defeated by any comment edit. The Phase 8c/10 gates instead assert that specific, named test titles exist in the real test files (`sourceHas(foundationTest, /apply then invert is identity for %s/)`, etc.), via `scripts/contract-utils.mjs`'s `sourceHas`, which strips comments first specifically so "documentation cannot satisfy a gate" (a direct, explicit fix for exactly the failure mode the prior audit found). A renamed or deleted test breaks the gate immediately; a comment edit does not.
- **Real limitation, stated plainly rather than discovered by an outside auditor this time:** these gates verify a named test *exists*, not that it *passes* or that its assertions are actually correct — the gate script itself does not execute any test. That trust is delegated to the CI step that runs `pnpm run test` separately from `pnpm run lint`. This audit closed that gap the only way possible short of the gate script running tests itself: by actually running the suites (§2, C4/C5) and confirming the counts match.
- **`check-phase6-contract.mjs`'s Assertion 2 (table granularity) is the strongest of the bunch** — it doesn't check for a test's existence at all, it asserts the whole-table `replaceTable(` helper function **doesn't exist in source anywhere**, which is a structural absence check, not a text census. This is the same category of improvement the Phase 8c gate makes elsewhere (checking `table/commands.ts` directly for the absence of a helper, per this audit's own §2/C2 note).
- **`pnpm run lint`'s full chain now genuinely runs end-to-end**, including `docs:plugins:check` (which itself builds `smartrte-core` and diffs generated plugin docs against committed ones — "5 plugin doc(s) up to date") and both packages' real `tsc --noEmit`. This directly closes the Phase 1–8b audit's Critical finding that the `&&`-chained lint script aborted early and never reached the per-package typecheck.

**No gate script in this project currently executes generated/rendered output or runs a real browser** — that remains true, same as the prior audit's finding, and remains an accurate characterization rather than a defect: the gates are static-source contracts; the e2e suite is where behavioral verification actually happens, and this audit ran that suite directly rather than trusting any gate's proxy for it.

### High

### Medium

- **151-file uncommitted working tree, comprising the entirety of Phases 10 through 12a.** §0. Not a code defect, but a real operational risk: this work is one `git stash --include-untracked` mishap, `git clean -fd`, or bad `git checkout` away from being lost, and this audit's own instructions had to explicitly warn against exactly that class of command. Not urgent — it's classified as `expected-normalization` with a strong (if not 100%-confirmed) circumstantial explanation already on file — but it is exactly the kind of loose end this project's own ledger discipline exists to prevent from becoming permanently forgotten.

Worth eventually clearing as ordinary dependency maintenance (major version bump, real compatibility risk, not urgent).

## 6. Phase 12b readiness assessment

**This audit finds no blocker specific to code quality or gate integrity for continuing toward Phase 12b.** The prerequisites the roadmap itself names ("all six collab-readiness assertions green and having stayed green since 8c") are independently confirmed green today (§2, C2).

**What should happen before Phase 12b, in priority order:**

1. **Commit the working tree (§0).** This is not optional housekeeping — Phase 12b is described in the roadmap itself as "comparable in effort to Phases 1–11 combined," and starting a project of that size on top of 151 uncommitted files across four already-shipped phases is a real risk, independent of anything else in this report.
2. **Fix or re-verify the one e2e flake (§4 Low)** — run the full suite once more; if it reproduces, treat it like `webkit-full-suite-timeout-flake.md` was treated (root-cause it as infra, not product); if it doesn't, downgrade the bug entry to "Not a bug" and move on. Cheap to resolve, worth resolving before it's forgotten which of the two it was.
3. **Give `table.mergeCells`'s Gate 13 divergence (§4 Medium) actual owner disposition** — it's been outstanding since before Phase 9 started and has now survived four more phases unaddressed. Low effort (read one diff, confirm or reject the existing hypothesis), meaningfully closes a loose end before a much bigger phase begins.
4. **Fix or explicitly accept the new `atom.attrs.error` rendering gap (§4 Medium)** — small, isolated, does not block anything architecturally, but it's a real UX gap for any host actually using `MediaProvider` in production today.

**Not blockers, but worth deliberate scoping decisions before or early in Phase 12b, since the roadmap itself flags 12b as the point where these become load-bearing rather than deferrable:**
- The ~37 unaudited `removeNode`/`replaceNode` sites (§2, C8) — Phase 12a correctly scoped auditing all of them out, but Phase 12b's multi-writer transaction model is exactly the context where a silently-orphaned annotation range (comment, suggestion) on one of these unaudited paths stops being a single-user inconvenience and starts being the kind of data-loss bug collaborative editing can't tolerate.
- Structural insertion suggestions remaining unsupported (§2, C7) is fine for v1.1 as shipped, but is worth resolving (or explicitly re-deferring with a fresh look) before real-time collaboration adds concurrent structural proposals to the mix.

**Bottom line: green-lit to proceed to Phase 12b planning, conditional on items 1–2 above being closed first** (both are cheap), and with items 3–4 and the two "worth scoping" notes carried forward as a named punch list rather than left to be rediscovered from scratch, which is exactly the failure mode this project's own audit history (`docs/PHASE_1_8B_INDEPENDENT_AUDIT.md`, the Gate 13/14 items now three phases stale) keeps demonstrating is real.
